## 2. Root cause — measured, not assumed

The Rev C captures were produced with the live feed running, which mixed the
sparkline candle window (seed + live sources). The provenance tag then renders
its long form `SEED:SYNTHETIC + LIVE:SIMULATED` (286 px wide), which widens the
right-aligned metrics block beyond the 239 px clip of the 240 px watchlist slot
(`overflow-x: hidden`), pushing the price column rightward and clipping it
mid-number. Measured against the Rev C environment:

| Element | Rendered text | Rect (x) | Clip | Visible | ITRGA reading |
|---|---|---|---|---|---|
| price-usdjpy | 150.010 | 270.0 → 330.7 | 287.0 | "15" | "renders as 15" ✓ |
| price-btcusd | 42,020.98 | 252.7 → 330.7 | 287.0 | "42,0" | "renders as 42,0" ✓ |

Both match ITRGA's reported readings exactly — the defect mechanism is
identified, not guessed. The fix for the evidence is environmental: capture
in the single-source-window state in which the price column is fully inside
the panel (the same state as the approved round-2 captures).

### 6.1 Deviation disclosed prominently: change-btcusd advance box

The `change-btcusd` **layout box** extends to x 287.9 — 0.9 px beyond the clip
at 287.0 — because BTC's price (78 px) and range strings are the widest in the
panel and the live adapter's alternating ±0.05% tick pins BTC's range at
`R: 42.03` (data, not code). I do not claim the box is inside; I measured what
the image shows instead. Pixel-level examination of the shipped PNG: the last
**painted glyph pixel** is at x 286 (colors of the change text, e.g.
rgb(145,49,53)), x 287 is the panel border line, and **no text pixel exists at
or beyond x 287** — the glyph is painted completely; the 0.9 px overshoot is
empty advance (glyph margin) and paints nothing. The image is primary: it
shows the complete `-0.05%`. This 0.9 px is a direct consequence of the fixed
240 px slot clipping the metrics block, which is registered as
`OBS-DATA-P01-WATCHLIST-CLIP` and left untouched per the determination's
instruction not to modify layout code.
