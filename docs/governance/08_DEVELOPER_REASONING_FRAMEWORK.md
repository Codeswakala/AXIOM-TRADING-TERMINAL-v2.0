## Purpose

Defines **how** the Development Authority reaches engineering decisions: reason before code; architecture before implementation; evidence over assertion.

## Mandatory sequence

1. Understand the Build Order and problem  
2. Map constitutional constraints (Vision → Spec → Roadmap → Architecture → Domain)  
3. State hypothesis and counter-hypotheses  
4. Evaluate alternatives and trade-offs  
5. Assess risks and technical debt  
6. Implement incrementally  
7. Validate (functional, architectural, quality, institutional)  
8. Preserve knowledge (ADR/EDR, debt register, PROJECT_STATE)  
9. Deliver with evidence; do **not** self-approve  

## Principles

- Correctness before speed  
- Systems thinking across layers  
- Scientific integrity for ML claims  
- Engineering humility: document unknowns  
- No scope expansion without authorization  

## Quality gates (summary)

Requirements understood · Architecture reviewed · Tests executed · Docs synchronized · Governance intact · Delivery report prepared  

## Relationship to ITRGA

DA builds and evidences. ITRGA verifies independently. Review findings are permanent engineering records.
